# Журнал лабораторных работ

## ЛР1. Стенд и сбор данных

### Стенд и вариант

- Источник: GH Archive, публичные события GitHub.
- Вариант: 31.
- Среда работы: Ubuntu в WSL на Windows, Docker и Docker Compose.
- Фильтр: PullRequestEvent, IssuesEvent, IssueCommentEvent.
- Режим службы: record.
- Предел закрытых файлов stream + history: 20 ГБ.
- Сборщик расположен в collector/src/main.py.
- Используется стандартная библиотека Python; новых зависимостей
  для обязательной части сборщика не добавлено.

### Решения по сборщику

1. Поток реализован последовательной загрузкой новых часовых архивов.
   История использует те же архивы за заданный период.

2. Фильтр применяется по полю type.
   event_key берётся из id; event_time — из created_at и приводится к UTC.
   received_at соответствует времени обработки события сборщиком.

3. Архив скачивается на диск небольшими блоками и читается построчно.
   Весь распакованный архив не накапливается в памяти.

4. Сохранённые события имеют формат JSONL и сжимаются gzip.
   Поток раскладывается по часу получения, история — по дате события.

5. Выход сначала записывается во временные файлы.
   Готовые файлы публикуются переименованием после проверки исходного gzip.
   Позиция часа фиксируется после публикации файлов.

6. SQLite хранит обработанные часы и индекс ключей событий.
   После перезапуска сборщик восстанавливает индекс готовых файлов
   и продолжает с сохранённой позиции.
   Индекс повторов разделён между record и backfill.

7. При ошибках применяется повтор с растущей паузой.
   Ответ Retry-After учитывается.
   Неопубликованный час не пропускается.

8. Предел хранения обеспечивается удалением самых старых закрытых файлов.
   Каталог state не входит в этот предел.

9. Журнал выводится строками JSON с ts, level, msg и показателями обработки.


### Сетевой сбой и решение

Полная загрузка через data.gharchive.org многократно завершалась таймаутом.
Проверки curl и urllib воспроизвели зависание и вне основного сборщика.
После получения приблизительно 16–19 КБ передача переставала продвигаться.

Через прямой адрес Google Cloud Storage тестовый архив скачался полностью:
15 358 706 байт примерно за 14 секунд. Размер и ETag совпали с исходным ответом.

В COLLECTOR_BASE_URL задано:

https://storage.googleapis.com/data.gharchive.org

Точная причина зависания старого сетевого маршрута не установлена.
Изменение Python-кода для переключения адреса не потребовалось.

### Измерение объёма

Выбран интервал из 20 полных архивных часов:

[2026-10-13T18:00:00Z, 2026-10-14T14:00:00Z).

Первоначальная догрузка накопившихся часов исключена из замера.
Суточные объёмы являются пересчётом 20-часового интервала, а не отдельным
замером полных суток.

| Показатель | Значение |
|---|---:|
| Прочитано до фильтра | 1 757 811 событий |
| Сохранено после фильтра | 44 255 событий |
| До фильтра | 1464,8425 события/мин |
| После фильтра | 36,8792 события/мин |
| Исходный JSONL | 1 447 246 317 байт |
| Исходные gzip-архивы | 307 049 652 байта |
| Сохранённый JSONL | 261 190 398 байт |
| Сохранённые gzip-файлы | 55 845 367 байт |
| Расчётный gzip потока в сутки | 67 014 440,4 байта |
| Исторический срез gzip | 692 649 852 байта |
| Восемь недель потока + история | 4 445 458 514,4 байта |

Проверка сохранённых файлов:

```bash
set -o pipefail

lr1_files=(
  data/raw/stream/dt=2026-10-13/hour={19..23}/*.jsonl.gz
  data/raw/stream/dt=2026-10-14/hour={00..14}/*.jsonl.gz
)

zcat "${lr1_files[@]}" | wc -l
zcat "${lr1_files[@]}" | wc -c
stat -c %s "${lr1_files[@]}" | awk '{s += $1} END {printf "%.0f\n", s}'

find data/raw/history -type f -name '*.jsonl.gz' -printf '%s\n' \
  | awk '{s += $1} END {printf "%.0f\n", s}'
```

Получено соответственно:

```text
44255
261190398
55845367
692649852
```

Число событий и размеры потока совпали с суммой показателей журнала.
Прогноз восьми недель потока с историей — приблизительно 4,45 ГБ,
что меньше предела 20 ГБ.
Ожидаемое первое ограничение по глубине хранения — заданный предел диска.

### Проверка содержимого

Во всём собранном stream + history выполнена проверка:

- source равен github;
- type входит в три типа фильтра;
- event_key — непустая строка;
- event_time и received_at имеют формат ISO 8601 с миллисекундами и Z.

Число нарушений — 0. Во время проверки ошибок чтения gzip и разбора JSON
в предоставленном выводе не было.


```bash
zcat data/raw/stream/dt=2026-10-14/hour=*/*.jsonl.gz \
  | jq -r .event_key | sort | uniq -d | wc -l
```
