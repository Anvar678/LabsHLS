# Служба сборщика данных

Оболочка службы. Программу сборщика пишет студент — в стенде её нет.

- Программа кладётся в `collector/src/`, точка входа — `main.py`.
- Зависимости — строками в `collector/requirements.txt`, затем
  `docker compose build collector`.
- Режим приходит первым аргументом и в переменной `COLLECTOR_MODE`:
  `record` (запись), `backfill` (загрузка истории), `produce` (отправка в
  брокер), `replay` (повтор записанного как потока). Режим службы задаёт
  `COLLECTOR_MODE` в `.env`; разовые режимы —
  `docker compose run --rm collector <режим>`.
- Слой сырых данных — `/data/raw` в контейнере, `data/raw` в каталоге стенда.
  Каталог вывода режима приходит в `COLLECTOR_OUT_DIR`: запись потока —
  `/data/raw/stream`, загрузка истории — `/data/raw/history`; повтор читает
  оба.
- Параметры источника из `.env`: `SOURCE` (значение оси), `SOURCE_FILTER`
  (фильтр потока из задания варианта, пусто — без фильтра),
  `COLLECTOR_RAW_LIMIT_GB` (предел объёма слоя сырых данных — при его
  достижении удаляются самые старые файлы).
- Файлы слоя сырых данных пишутся сжатыми. С работы 3 закрытые файлы
  копируются в озеро под префикс `COLLECTOR_LAKE_PREFIX` (пусто — копирование
  выключено); адрес и ключи хранилища — переменные `S3_*` из `.env`.
- Порт счётчиков — 9101.

Полный контракт сборщика — раздел «Контракт сборщика данных» методических
указаний; здесь только то, что задаёт оболочка.
