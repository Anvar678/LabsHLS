# Паспорт источника: GH Archive

Вариант 31. Источник — публичные события GitHub.

## Доступ

- Описание источника: https://www.gharchive.org/
- Основной адрес часовых архивов: https://data.gharchive.org/
- Рабочий адрес сборщика: https://storage.googleapis.com/data.gharchive.org/
- Имя архива: ГГГГ-ММ-ДД-ЧАС.json.gz; час UTC без ведущего нуля.
- Поток получается загрузкой каждого нового часового архива после его публикации.
- История загружается тем же способом: это те же события и идентификаторы.
- По методическим указаниям история доступна с 12 февраля 2011 года.
- Загруженный исторический срез: [2026-10-05T12:00:00Z, 2026-10-12T12:00:00Z), семь суток, 168 часовых архивов.
- Исторический срез хранится отдельно от потока.

## Лицензия и условия использования

По разделу «Источники данных» методических указаний:

- код проекта GH Archive — MIT;
- материалы сайта — CC BY 4.0;
- события являются публичными данными GitHub; условия использования — GitHub Terms of Service.

Описание лицензии кода не рассматривается как отдельная лицензия событий.
Собранные данные используются на учебном стенде и не публикуются.

## Лимиты и представление клиента

- Объявленный численный лимит запросов отсутствует.
- Архивы скачиваются последовательно, по одному.
- Период ожидания нового завершённого часа — 60 секунд.
- Между успешно обработанными архивами предусмотрена пауза 1 секунда.
- При ошибках запрос повторяется с растущей паузой.
- При наличии Retry-After сборщик учитывает указанное источником ожидание.
- Каждый запрос передаёт User-Agent с названием сборщика и контактным email. Значение задаётся переменной COLLECTOR_USER_AGENT.
- Адрес источника задаётся переменной COLLECTOR_BASE_URL.

## Схема события

Исходные поля события сохраняются. Сборщик добавляет служебные поля.

| Поле | Тип в JSON | Смысл |
|---|---|---|
| id | строка | Идентификатор события GitHub |
| type | строка | Тип события |
| created_at | строка | Время события источника |
| actor | объект | Участник события |
| repo | объект | Репозиторий |
| payload | объект | Содержимое события; структура зависит от type |
| public | логическое значение | Признак публичности |
| event_key | строка | Ключ события, строковое представление id |
| event_time | строка | created_at, приведённое к UTC с миллисекундами |
| received_at | строка | Время получения и обработки события сборщиком, UTC с миллисекундами |
| source | строка | Значение github |

Формат event_time и received_at: ГГГГ-ММ-ДДTЧЧ:ММ:СС.мммZ.

Идентификатор id используется для исключения повторной записи события.
Индекс ключей ведётся отдельно для потока и истории.

## Фильтр потока и объёмы

Фильтр применяется по полю type:

- PullRequestEvent;
- IssuesEvent;
- IssueCommentEvent.

### Интервал измерения

Измерены 20 полных часовых архивов:

[2026-10-13T18:00:00Z, 2026-10-14T14:00:00Z).

Файлы потока выбраны из партиций времени получения:

- dt=2026-10-13/hour=19..23;
- dt=2026-10-14/hour=00..14.

Первоначальная догрузка накопившихся часов в этот замер не включена.

За интервал прочитано 1 757 811 событий, сохранено после фильтра 44 255.
Число строк и размеры сохранённых файлов совпали с суммой показателей журнала.

Длительность измерения — 20 архивных часов. Суточные значения ниже являются
пересчётом по формуле: значение за интервал × 24 / 20.
Это не утверждение о проведённом отдельном замере полных суток.

### Предел хранения

Используются десятичные единицы: 1 ГБ = 1 000 000 000 байт.

- Предел stream + history: 20 000 000 000 байт.
- Измеренный размер исторического среза: 692 649 852 байта.
- Восемь недель потока: 56 × 67 014 440,4 = 3 752 808 662,4 байта.
- Поток за восемь недель вместе с историей:
  3 752 808 662,4 + 692 649 852 = 4 445 458 514,4 байта, приблизительно 4,45 ГБ.

По этому прогнозу восьминедельный поток вместе с историей помещается в предел.
Оценка предполагает сохранение средней интенсивности и состава событий
из измеренного интервала.

Первое ожидаемое ограничение при росте объёма — заданный предел хранения:
при росте приблизительно в 5,1 раза восьминедельный поток с текущим
историческим срезом уже не поместится в 20 ГБ. Это оценка по объёму хранения,
а не результат нагрузочного испытания сети, CPU или памяти.

При достижении предела сборщик удаляет самые старые закрытые файлы.
Служебный каталог state не входит в установленный предел stream + history,
но занимает место на диске.

## Известные дефекты и особенности

1. Архив нового часа появляется с задержкой.
   В измеренном журнале первые запросы получали 404, а приблизительно через
   7–8 минут после окончания часа загрузка завершалась успешно.
   Сборщик сохранял позицию и повторял запрос.

2. Полная загрузка через data.gharchive.org на данном сетевом маршруте
   останавливалась примерно после 16–19 КБ.
   Прямой адрес Google Cloud Storage позволил скачать архив полностью.
   Размер и ETag тестового архива совпали.
   Точная причина сетевого ограничения не установлена.

3. По методическим указаниям отдельные часовые архивы могут быть неполными.
   Сборщик проверяет Content-Length, чтение gzip до конца и сравнивает размер
   с предыдущим часом. Порог по умолчанию — 20% предыдущего размера.
   Сравнение размеров является эвристикой и не доказывает абсолютную полноту
   событий источника.

4. Во всём проверенном stream + history не найдено нарушений фильтра,
   source, непустого строкового event_key и формата временных полей.
   Повторяющихся ключей в потоке за 14 октября 2026 года не найдено.
